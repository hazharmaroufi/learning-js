# جلسه‌ی ۱۴ نوامبر ۲۰۲۶ — Object references (هفته ۲، روز ۲، بخش اول)

منبع: javascript.info ← Object references and copying (تا آخر بخش Comparison by reference)

## اصلاح `productInfo`
- پرانتز اضافه دور `return` را برداشتم. باگ نبود، عادت بد بود: `return` دستور است، نه تابع.
- تنها جایی که پرانتز دور مقدار `return` لازم می‌شود: وقتی مقدار برگشتی چند خط باشد.
- پارامتر تابع را با destructuring نوشتم: `function productInfo({ name, price, inStock })`

## سؤال ۱ — کپی کردن متغیر
```js
const drill = { price: 100 };
const copy = drill;
copy.price = 200;
console.log(drill.price); // 200
```
حدس من: 200 ✅
دلیل: هر دو به یک مکان در حافظه اشاره می‌کنند.

نکته: متغیر خودِ شیء را نگه نمی‌دارد، **نشانی** آن را نگه می‌دارد. `const copy = drill` فقط نشانی را کپی می‌کند.

## سؤال ۲ — مقایسه
```js
const a = { price: 100 };
const b = { price: 100 };
const c = a;

console.log(a === b); // false
console.log(a === c); // true
```
حدس من: false و true ✅
دلیل: `a` و `b` به دو مکان **جدا** اشاره می‌کنند که محتوایشان شبیه هم است (دو دریل هم‌مدل در دو قفسه). `a` و `c` به یک مکان.

## سؤال ۳ — با `==`
```js
console.log(a == b); // false
```
حدس من: false ✅

## قانون‌های امروز
1. متغیرِ شیء نشانی را نگه می‌دارد، نه خود شیء را.
2. کپی کردن متغیر = کپی کردن نشانی. تغییر از یکی، از دیگری هم دیده می‌شود.
3. برای اشیاء `==` و `===` فرقی ندارند: هر دو فقط می‌پرسند «آیا به یک مکان اشاره می‌کنند؟»
4. دو شیء جدا، حتی با محتوای یکسان، هیچ‌وقت برابر نیستند.
